# A2 Pro 전후방 인식·위험 추적 — 1단계

대상: 사용자 확인 Unitree A2 Pro + 외장 Jetson Orin NX 16GB.

## 구현 범위와 실행 상태

- 브라우저: 전방/후방 시야 전환, 전후방 여유거리·TTC·위험도·객체 종류 표시.
- `src/a2/perception.js`: 카메라 분류/방향 + LiDAR 객체 군집 입력 계약, 월드 좌표 추적, 자기 움직임 보정, 상대 충돌 예측.
- worker에서 10Hz로 **가상 객체 입력**을 생성하여 추적기를 실행한다. 후방 위험은 경광등 이벤트로도 표시한다.
- `deploy/jetson/vision.py`: 별도로 준비한 경량 ONNX 탐지기를 한 장의 보정 영상에 실행하는 오프라인 어댑터. 사람/자동차의 종류·신뢰도·방향을 출력한다. 새로운 배포 번들에 이 파일도 포함한다.

**중요:** 브라우저는 화면 픽셀에 AI를 실행하지 않는다. 시뮬레이터 객체의 위치·종류를 가상 센서 관측으로 변환한다. LiDAR ray casting, 실제 가림/반사/노이즈, 원시 포인트클라우드 군집화도 아직 없다. 화면에 SIM / SHADOW를 표시한다. 신규 위험 추적 결과는 아직 주행 명령에 연결하지 않고 **표시 전용**으로 검증한다. 기존 회피기가 계속 주행을 담당한다.

실기 카메라/전후방 LiDAR 드라이버, Jetson 스트림 수신, 학습된 탐지 가중치, 실시간 센서 융합 서비스, SDK 송신은 이 단계에 포함되지 않는다. 실제 장비 사양/보정값을 읽었다고 주장하지 않는다.

## 흐름

```text
경량 영상 탐지 → person/car + confidence + body bearing ┐
보정된 LiDAR 군집 → body x/y + 외접 반경                ├→ 월드 추적 → 전후방 위험/TTC
시각 동기된 몸체 위치·yaw                              ┘                  ↓
                                                        현재: 화면·경광등만
                                                        이후: 검증된 안전 중재기
```

카메라 분류가 없거나 모호해도 LiDAR 장애물은 `unknown`으로 유지한다. 영상만으로 거리를 만들어내지 않는다. 추적 ID는 시뮬레이터 ID를 가져오지 않고 이전 위치/속도 예측과 최근접 대응으로 생성한다. 로봇의 평행 이동·회전을 월드 좌표로 보정한 뒤 상대 속도로 충돌을 예측한다.

현재 대응은 단순 최근접 방식이다. 교차/밀집 군집에서는 ID 교환 가능성이 있어 실기 사용 전 더 강한 데이터 연결, 불확실성 관리 및 위치추정 오류 검증이 필요하다. 방향이 비슷한 군집이 여러 개이면 영상 클래스 연결을 거부한다. 가림을 재현하지 않는 가상 입력 특성상 탐지 성능 평가 자료로 사용할 수 없다.

## 입력 계약

단위: 미터, 초, 라디안. 몸체 +X 전방/+Y 왼쪽. `pose`는 일관된 월드 좌표의 몸체 위치/yaw. 모든 stamp는 같은 단조 시간 기준이며 pose/군집/영상 관측은 센서 어댑터에서 시각 정합해야 한다.

```js
{
  source: 'simulation-ground-truth', // 실제 연결 시 출처를 구분
  stamp: 12.3,
  pose: { x: 1, y: 0, yaw: 0 },
  lidar: { stamp: 12.3, clusters: [{ x: -1.8, y: 0, radius: 0.3 }] },
  cameras: {
    front: { stamp: 12.3, detections: [] },
    rear: { stamp: 12.3, detections: [{ bearing: Math.PI, confidence: 0.9, kind: 'person' }] }
  }
}
```

LiDAR 입력은 전후방 스캔을 동일 몸체 프레임으로 합치고 중복을 제거한 **객체 군집**이다. 원시 point cloud 토픽을 그대로 넘기지 않는다. 군집 radius는 수평면상의 보수적 외접 반경이다. 자기 몸·박스·팔·지면 필터링은 실기 어댑터에서 별도 구현해야 한다.

센서 age 한도 0.3초, 추적 유지 0.5초, 충돌 예측 2초는 초기 시험값이다. 늦거나 누락된 LiDAR/pose, 비정상 수치 또는 역순 프레임은 `unknown`으로 반환한다. 영상만 누락되면 `degraded`로 거리 추적은 유지한다. 짧은 관측 누락은 예측 위치를 유지한 뒤 TTL이 지나면 추적을 만료한다. `clear`는 관측 범위에서 현재 모델이 위험을 찾지 못했다는 의미이지 전체 공간의 안전 인증이 아니다.

몸체/발 동작 범위를 포함한 사각형을 군집 반경으로 팽창시킨 뒤 등속 상대 궤적과 교차 시간을 계산한다. TTC < 0.7초는 critical, 2초 이내는 warning, 충돌 궤적은 없지만 여유거리 < 0.5m는 near다. 미래 회전, 제동/가속도, 보행 진동, 센서 오차는 아직 이 TTC 모델에 포함되지 않는다. 정지/탈출 결정을 이 수치만으로 내리지 않는다.

## 카메라 시야와 초기 처리량

- 가상 시야: 수평 78°, 전후방 카메라 위치는 시뮬레이터용 가정이며 실측 사양이 아니다.
- 가상 LiDAR 객체 관측 범위: 8m, 가림 없는 2D 입력. 실물 스캔 범위/주사 주기를 의미하지 않는다.
- 실제 영상 탐지는 우선 고정 입력 약 640×384, 전후방 각각 10~15FPS를 시험 목표로 삼는다. 모델이 지원하는 크기에 맞춰야 하며 Orin NX에서 이 성능을 확인한 것은 아니다.
- GPU 모델을 프레임마다 다시 생성하지 않는다. 현재 `vision.py`는 1회 오프라인 검증 도구이므로 프로세스/세션을 반복 호출하는 실시간 루프로 사용하지 않는다. 실시간 서비스 단계에서 모델 세션을 공유하고 큐를 제한해야 한다.

## 오프라인 ONNX 영상 어댑터

지원하는 탐지기 계약:

- 입력 하나: RGB, float32, `[1,3,H,W]`, 값 0..1, letterbox 114.
- 출력 하나: NMS 완료 `[1,N,6]`, 각 행은 `x1,y1,x2,y2,score,class_id`.
- 좌표는 letterbox 입력 픽셀, 클래스는 COCO person=0/car=2 가정.
- raw YOLO head, 정규화 좌표 출력, 다른 label mapping은 별도 export/후처리 어댑터가 필요하다.
- 가중치는 포함/자동 다운로드하지 않는다. 정확도·라이선스·JetPack 호환성을 검증한 경량 모델을 준비한다. 기존 배포기의 body-velocity `policy.onnx`와 탐지기 모델은 다른 종류이며 혼용하지 않는다.

```bash
python3 deploy/jetson/vision.py \
  --model /absolute/path/detector_nms.onnx \
  --image /absolute/path/rear_rectified.png \
  --camera rear --fx 500 --cx 320
```

`fx=500`, `cx=320`은 **명령 형식 예시**다. 반드시 왜곡 보정된 해당 영상의 실제 내부 보정값으로 바꾼다. 어댑터는 정렬된 전방 yaw=0/후방 yaw=π인 이상적 카메라를 가정한다. 실제 카메라의 pitch/roll/yaw·몸체 원점과의 이동량, LiDAR 투영은 현장 보정 후 더 일반적인 외부 파라미터 어댑터로 확장해야 한다. 출력에는 촬영 시각/거리를 임의로 붙이지 않는다.

필요 패키지는 `numpy`, 호환 `onnxruntime` 및 `opencv-python-headless`다. 기존 Jetson 설치 절차의 고정 wheel/해시 방식으로 준비한다. 출력의 `inference_ms`는 1회 추론(초기 워밍업 포함 가능)이며 실시간 성능 인증이 아니다.

## 실기로 진행할 다음 순서

1. 실제 전후방 영상·LiDAR 스트림 접근 확인과 JetPack 버전 확인.
2. 짧은 센서 로그 및 보정값 확보. Jetson 박스/팔에 의한 후방 가림 확인.
3. 실제 경량 탐지 모델을 선택하고 오프라인 영상에서 person/car 검출 검증.
4. LiDAR 객체 군집화·시간 정합·외부 파라미터 변환 구현, 기록 로그로 추적 검증.
5. Jetson 실시간 shadow 서비스에서 전체 지연·누락·온도·전력 시험.
6. 후방 접근/횡단/추적 손실/전방 막힘/Manual 전환 검증 후 안전 중재기에 연결.

사람 접근을 감지했다고 무조건 전진하지 않는다. 전진 탈출 경로·전방 장애물·다른 이동체·로봇 제동 특성을 확인한 경우에만 선택해야 한다. 기존 후방 탈출 로직과 신규 추적기의 차이를 먼저 비교 검증한다.
